## Harness的设计原则

* 控制反转（IoC）：业务流程的控制权从“Go/Python 代码”完全转移到了“大模型的实时推理和规划”中。代码只提供物理定律（如文件读写和编辑、沙箱执行等），不干涉任务走向。
* 防线前移动：既然大模型是自由的，它就可能犯错或搞破坏。因此 Harness 的核心代码全部集中在了 Middleware（防止搞破坏）和 Compactor（防止内存被撑爆）上。
* 状态透明：循环值依赖一个单一的数据结构——也就是不断累加的 Context 消息列表。没有任何隐式的树节点或图节点变量。

## 架构图及分层解析

* 入口交互层：引擎对外的触角。
  * CLI
  * 飞书
  * 人工审批拦截
* 核心引擎层（心脏）：系统的控制中枢。
  * Mainloop 核心 ReAct 循环
    * 慢思考
    * 大模型适配层
* 上下文工程层（内存管理器）：决定 Agent 能够跑多远的关键。
  * Prompt 动态组装器：注入 AGENTS.md
  * Token 监控与阶梯压缩器
  * 运行时事件提醒注入：斩断死循环
  * 基于文件系统的外部化记忆：PLAN/TODO
* 工具与执行层（四肢与手脚）：挂载了让模型改变物理世界的组件。
  * Read File
  * Write File
  * Edit File
  * Bash Execution
